# Aegis-Boot (神盾) 前端对接与接口规范终极指南 (v1.1.0-Security)

本指南为 **Aegis-Boot (神盾 · 现代安全开发架构)** 的官方配套前端集成与全量接口规范手册。涵盖了系统多端架构划分、无状态会话物理隔离、第三方社交登录闭环交互、通用高安全 CRUD（基于 `BaseController`）等核心业务接口的入参、出参、参数实体大字典及详细安全规范。

---

## 1. 核心架构与多端会话物理隔离

Aegis-Boot 采用标准的前后端分离、无状态分布式认证架构。为了在多层级、多渠道的复杂业务下提供极高安全防护，系统在底层对 **B端企业管理端**、**C端普通用户端** 与 **公共无状态端** 实施了严格的“沙箱隔离”及物理会话互斥机制。

### 1.1 端点角色与会话特征

| 客户端群 (端点分类) | 物理路由前缀 | 会话检验引擎 | 底层映射实体 | 安全防护特征与鉴权逻辑 |
| :--- | :--- | :--- | :--- | :--- |
| **B端管理员端 (Admin)** | `/api/admin/**`<br>`/sys/**` | `StpUtil`<br>(会话类型: `login`) | `sys_user` (管理员账号) | **网关级动态无注解权限对碰**。开发时无需声明注解，物理路由在系统启动时自动全量同步。每次请求由 Sa-Token 从 Redis 缓存读取对应的管理员 `sys_api` 权限集合并实时匹配。未登录返回 `1001`，未授权返回 `1008`。 |
| **C端普通用户端 (Portal)** | `/api/user/**` | `StpUserUtil`<br>(会话类型: `user`) | `sys_user` (C端档案)<br>`sys_user_social` | **物理隔离会话**。Token 签发和 Redis 存储独立，彻底隔离 B 端与 C 端的鉴权上下文。杜绝由于两端 ID 相同导致的水平越权高危漏洞。 |
| **公共免签端 (Common)** | `/api/common/**` | 无状态豁免放行 | 免登录 (游客) | **豁免安全防火墙**。通常用于获取静态配置、第三方授权接收、公共枚举等。**特例**：公共文件上传/删除高危物理接口被加固，强制实施「B端/C端双端登录联合防御」，至少需持有一端有效 Token。 |

## 2. 统一底层交互协议

### 2.1 统一响应结构 `Result<T>`
无论调用何种业务接口、成功或失败，后端均返回标准一致的 JSON 格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

#### 响应结果成员字段解析：
*   **`code`** (Integer): 状态码。`200` 代表业务处理成功，其余数值均为异常状态。
*   **`message`** (String): 接口返回的文字消息（如成功提示、校验失败、系统错误原因等）。
*   **`data`** (T / Object / Array / Null): 承载的具体业务实体、分页对象、或者字符串凭证。其具体数据结构由特定接口决定，操作失败或无返回数据时统一为 `null`。

### 2.2 全局错误码对照表 (`ResultCode`)
当前端拦截到返回体中 `code != 200` 时，应当根据以下标准字典码表做出对应的客户端路由拦截、清空会话、或 UI 警告弹窗行为：

| 错误码 (`code`) | 默认提示消息 (`message`) | 分类与推荐前端处理行为 |
| :--- | :--- | :--- |
| **200** | 操作成功 | **放行**：执行正常的视图数据渲染。 |
| **2001** | 操作失败 | **Toast 提示**：普通业务级别失败，推荐使用 Toast 或 Banner 进行警告提示。 |
| **1001** | 当前会话未登录 | **重定向登录**：会话未登录，清空本地 Token 缓存并强制跳转至宿主环境登录页。 |
| **1002** | 未能读取到有效Token | **重定向登录**：请求头缺失凭证。直接拦截并引导登录。 |
| **1003** | Token无效 | **重定向登录**：Token 伪造、格式破损或校验不通过。清空状态并引导至登录页。 |
| **1004** | Token已过期 | **重定向登录**：会话超时过期。清空 Token 缓存，重新引导登录。 |
| **1005** | Token已被顶下线 | **异地强退警示**：发生同账号多地挤占登录。弹出“异地登录”警示并重定向。 |
| **1006** | Token已被踢下线 | **强退强通知**：被管理员在后台强制收回会话。弹出强退通知，清空状态跳转。 |
| **1007** | Token已被冻结 | **Toast 提示**：当前账号状态异常已被封禁。限制用户进行敏感受限操作。 |
| **1008** | 无权限，请联系管理员 | **403 阻断**：当前用户所属角色不具备该物理 `Path + Method` 权限。提示权限不足并返回原页面。 |
| **1009** | 无此角色权限 | **403 阻断**：当前用户的角色类型（Role）不匹配。 |
| **1010** | 防火墙拦截 | **高危安全阻隔**：参数触发 `Sa-Firewall` 安全拦截过滤（如SQL注入、跨站字符）。强制拒绝访问。 |
| **4001** | 参数无效 | **校验失败**：未通过 Spring Validator 参数格式、必填项约束校验。前端高亮输入框并提示。 |
| **4002** | 参数为空 | **校验失败**：请求体（RequestBody）为空。 |
| **4003** | 参数类型错误 | **校验失败**：参数类型不匹配（例如前端传 String，后端强类型绑定为 Long 且无法转化）。 |
| **4004** | 参数缺失 | **校验失败**：URL Querystring 中缺少必要的传参（例如分页接口漏传 current）。 |
| **5001** | 系统繁忙，未知错误，请稍后再试 | **500 页面**：后端内部抛出未捕获的运行时异常（NullPointer 等）。展现友好报错页。 |
| **5002** | 数据库操作异常 | **500 页面**：后端数据库连接失败、SQL语法错或事务冲突。 |
| **5003** | 不支持的请求方法 | **路由警示**：HTTP Method 错误（例如接口要求 POST，前端误写为 GET）。 |
| **5004** | 您访问 of 资源不存在 | **404 页面**：服务端物理路径不存在。 |
| **6001** | 业务执行异常 | **Toast 提示**：核心业务逻辑抛出的异常（例如余额不足），直接渲染返回的 message 内容。 |

### 2.3 请求凭证 (Token) 携带规范
在发起任何需要受限鉴权的 API 请求时，**必须在 Request Headers 中携带对应的会话凭证**：
*   **Header Key**：`satoken` (一律小写)
*   **Header Value**：`[Token值]`（后端签发给客户端的纯 Hex/JWT 字符串，不需要携带 "Bearer" 等额外格式前缀，框架会自适应解析）。

### 2.4 Snowflake 精度丢失规避
为了规避 Java `Long` 类型雪花算法 ID (最大 64 位，例如 `19958742131238912`) 传递到 JavaScript 中因超出 JS 的安全整型限度 ($2^{53}-1 = 9007199254740991$) 产生的精度丢失（自动舍入截断）风险，Aegis-Boot 在后端启用了 **Jackson Precision Engine**：
*   所有传出的 `Long` 型字段（包括主键 `id`、业务 `bizId` 等）在序列化时**已自动转化为 `String` 类型字符串形式**。
*   前端在接收到 JSON 数据后，**必须将其作为 String 直接存储和使用**（切勿强行转换为 Number），且在随后作为参数或 Body 传回后端时原封不动作为 String 传回，后端在反序列化时能自适应逆向转换。

## 3. 全局通用公共模型定义

此部分定义了后端频繁复用的公共模型，以便于前端建立对应的 TypeScript 接口或统一解析类。

### 3.1 实体共有基础字段 (`BaseEntity`)
系统中所有数据库映射实体（SysFile, SysLog 等）均默认包含以下 3 个核心共有基础字段，返回结果中会无缝输出：

| 参数字段 | 类型 | 说明/详细含义 | 示例值 |
| :--- | :--- | :--- | :--- |
| **`id`** | String | 物理主键。雪花算法（Snowflake）生成的 64 位唯一长整型，通过 Jackson 自动转换为 String 形式输出，前端严禁将其还原为数字。 | `"19958742131238912"` |
| **`createTime`** | String | 创建时间。格式统一为 `yyyy-MM-dd HH:mm:ss`，在数据初次入库时由后端切面自动写入，不可修改。 | `"2026-06-04 12:00:00"` |
| **`updateTime`** | String | 更新时间。格式统一为 `yyyy-MM-dd HH:mm:ss`，在数据更新时由后端自动刷新，不可修改。 | `"2026-06-04 12:05:00"` |

### 3.2 统一分页数据包装模型 (`IPage<T>`)
所有查询分页接口成功后的 `data` 节点均会包装为此标准分页模型，其子节点 `records` 包含实际实体数组：

| 参数字段 | 类型 | 说明/详细含义 | 示例值 |
| :--- | :--- | :--- | :--- |
| **`records`** | Array\<T\> | 泛型实体数组。包含当前页满足查询过滤条件的所有数据行。 | `[ { ... }, { ... } ]` |
| **`total`** | Long | 数据总条数。数据库中满足查询条件的记录总数，用于计算和渲染分页组件的总页数和总容量。 | `150` |
| **`size`** | Long | 每页容量。前端所传入的单页显示上限数量。 | `10` |
| **`current`** | Long | 当前页码。前端请求访问的目标页码。 | `1` |
| **`pages`** | Long | 计算出的总页数。自动基于 `total` 和 `size` 换算。 | `15` |

## 4. 全量物理接口详细参数大字典 (逐一罗列)

### 4.1 认证授权模块 (AuthController)
物理访问基础路径：`/api/common/auth`  
本模块专门负责密码安全传输准备、注册、及多端物理会话建立。

#### 1) 获取网络传输加密公钥 (GET /rsa/public-key)
*   **物理地址**：`GET /api/common/auth/rsa/public-key`
*   **权限级别**：公共免签豁免（白名单放行）
*   **请求 Headers**：
    *   `Content-Type: application/json`
*   **请求参数**：无
*   **返回结果数据结构** (Result\<String\>)：
    *   `data` (String): 2048 位高安全标准非对称加密 RSA 公钥 Base64 文本。前端获取此公钥后，在注册或登录提交前，需对密码明文执行非对称加密，杜绝网络嗅探。
*   **请求示例**：
    ```http
    GET /api/common/auth/rsa/public-key HTTP/1.1
    Host: localhost:8080
    ```
*   **响应示例**：
    ```json
    {
      "code": 200,
      "message": "操作成功",
      "data": "MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA0G9h+H6vLp7DIs8T..."
    }
    ```

#### 2) C端普通用户端 密码安全注册 (POST /user/register)
*   **物理地址**：`POST /api/common/auth/user/register`
*   **权限级别**：公共免签豁免（白名单放行）
*   **请求 Headers**：
    *   `Content-Type: application/json`
*   **请求参数 (RequestBody - JSON)**：
    | 参数字段 | 类型 | 是否必填 | 校验规则 | 说明/详细含义 | 示例值 |
    | :--- | :--- | :--- | :--- | :--- | :--- |
    | **`username`** | String | 必填 | 不能为空，长度 4-20 位 | 用户登录账号名。系统全局唯一。 | `"portal_user_2026"` |
    | **`password`** | String | 必填 | 不能为空 | 密码非对称密文。必须将密码明文使用 1) 接口返回的 RSA 公钥加密，并生成 Base64 字符串。 | `"A7X6yN9...[RSA密文]"` |
*   **返回结果数据结构** (Result\<Null\>)：
    *   `data` 为 `null`。表示注册无实际实体返还，仅指示操作成功。
*   **请求示例**：
    ```json
    {
      "username": "portal_user_2026",
      "password": "OQo66I08L/qRAnDqQ6b3vR97x1oXf7V8F8l9K9pQ=="
    }
    ```
*   **响应示例**：
    ```json
    {
      "code": 200,
      "message": "操作成功",
      "data": null
    }
    ```

#### 3) C端普通用户端 密码安全登录 (POST /user/login)
*   **物理地址**：`POST /api/common/auth/user/login`
*   **权限级别**：公共免签豁免（白名单放行）
*   **请求 Headers**：
    *   `Content-Type: application/json`
*   **请求参数 (RequestBody - JSON)**：
    | 参数字段 | 类型 | 是否必填 | 校验规则 | 说明/详细含义 | 示例值 |
    | :--- | :--- | :--- | :--- | :--- | :--- |
    | **`username`** | String | 必填 | 不能为空 | 用户注册账号名。 | `"portal_user_2026"` |
    | **`password`** | String | 必填 | 不能为空 | 密码非对称密文。必须使用公钥加密。 | `"OQo66I08L/qRAnDqQ6b3vR97x1oXf7V8F8l9K9pQ=="` |
*   **返回结果数据结构** (Result\<LoginResultVO\>)：
    *   `data` (Object): 登录成功综合视图。成员属性如下：
        *   **`token`** (String): **C端专属用户会话凭证 Token**。前端需将其缓存在 `localStorage` 中。在随后请求 C端 `/api/user/**` 受限路由时，强制携带于 Headers `satoken: [Token值]`。

        *   **`roles`** (Array\<String\>): 当前登录人绑定的角色 Key 编码列表。
        *   **`permissions`** (Array\<String\>): 当前登录人持有的物理 API 拦截权限清单（格式：`METHOD:PATH`）。
*   **请求示例**：
    ```json
    {
      "username": "portal_user_2026",
      "password": "OQo66I08L/qRAnDqQ6b3vR97x1oXf7V8F8l9K9pQ=="
    }
    ```
*   **响应示例**：
    ```json
    {
      "code": 200,
      "message": "操作成功",
      "data": {
        "token": "b4b9dc70-76bc-4927-9002-390234a9712c",
        "userInfo": {
          "id": "19958742131238910",
          "username": "portal_user_2026",
          "userType": "USER",
          "status": 0,
          "createTime": "2026-06-04 12:00:00",
          "updateTime": "2026-06-04 12:00:00"
        },
        "roles": ["common_user"],
        "permissions": []
      }
    }
    ```

### 4.2 第三方社交登录模块 (OAuthController)
物理访问基础路径：`/api/common/oauth`  
本模块集成 JustAuth，实现第三方授权后自动创建本地 C 端账号映射、登录并分发 C 端 Token。

#### 1) 获取当前启用的社交登录平台通道列表 (GET /platforms)
*   **物理地址**：`GET /api/common/oauth/platforms`
*   **权限级别**：公共免签豁免
*   **请求 Headers**：
    *   `Content-Type: application/json`
*   **请求参数**：无
*   **返回结果数据结构** (Result\<List\<SocialPlatformVO\>\>)：
    *   `SocialPlatformVO` 实体字段：
        | 属性名称 | 类型 | 说明/详细含义 | 示例值 |
        | :--- | :--- | :--- | :--- |
        | **`code`** | String | 社交平台唯一英文标识。 | `"github"` |
        | **`name`** | String | 社交平台的友好中/英文名称。 | `"GitHub"` |
        | **`enabled`** | Boolean | 可用开关状态。`true` 代表后端已开启并配置了该平台的密钥，前端可直接渲染此登录按钮；`false` 建议置灰或隐藏。 | `true` |
*   **请求示例**：
    ```http
    GET /api/common/oauth/platforms HTTP/1.1
    Host: localhost:8080
    ```
*   **响应示例**：
    ```json
    {
      "code": 200,
      "message": "操作成功",
      "data": [
    ```

    *   `data` (String): 第三方平台物理授权重定向 URL，含有防跨站 State。


## 5. 前端最佳安全实践与联调规范

为了充分发挥 **Aegis-Boot (神盾)** 后端的高安全性效能，前端团队在联调和设计客户端代码时，必须强制落地执行以下防御规范：

### 5.1 非对称密码传输安全原则
*   **规范操作流程**：
    1. 在加载登录/注册表单前，异步调用 `GET /api/common/auth/rsa/public-key` 获取一次性的 RSA 公钥。
    2. 使用前端标准 JS 非对称加密库（如 `jsencrypt` 或 `node-forge`），利用该公钥将用户的输入明文密码进行强加密。
    3. 将生成的 Base64 强加密密文，装入 `password` 字段再行发起 Ajax 提交，确保其在传输全链路不可破译。

### 5.2 大数精度防截断方案
*   在前端 Axios 响应拦截或本地存储中，对后端主键、外键 `id` 类属性，一律将其当作纯 **String** 类型对待、渲染和传递。
*   严禁在 JavaScript 代码中对 `id` 属性执行 `Number()`、`parseInt()` 强制整型还原，以防导致大数位精度溢出被舍入截断，从而引发查询或增删时的主键对碰失效（数据“未找到”）。

### 5.3 全局 Axios 会话强拦截与重定向
*   在 HTTP 客户端（如 Axios Interceptor）的 Response 拦截器中，对 `code` 进行统一拦截：
    *   若捕获到返回状态码处于 **`1001` - `1006`** 之间（会话未登录、未读到 Token、过期、被顶替或强退下线），应当：
        1. 立即执行 `localStorage.clear()` 清空浏览器本地会话状态缓存。
        2. 根据当前处于 B端 (管理后台) 还是 C端 (用户应用)，**强制中断后续网络渲染，并自动拉回对应的引导登录地址**，保障受限资源完全不可越权访问。

### 5.4 防抖与节流流控防御
*   前端在触发写盘、敏感提交操作（如新增 `POST /save`，批量提交 `POST /saveBatch`，及上传物理文件等）的交互按钮时，必须强行配置完整的按钮 **`Loading 锁定状态`** 以及 **防抖（Debounce）/ 节流（Throttle）** 物理流控。
*   在按钮触发后 2-3 秒内拦截用户的连续快速双击，避免因网络波动或抖动产生的数据库主键碰撞或磁盘文件的脏盘产生，从客户端入口构建坚实防御。
